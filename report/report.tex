    \section{Task 2: Estimating $\pi$}\label{sec:task_2}                       % Example sections, subsections

    \subsection{Task description and methods}

    The goal of this task is to estimate $\pi$ using the area method and 1D Monte Carlo integration. Furthermore, the convergence speed of each method is observed by gradually increasing the number of samples $N$ and calculating the resulting approximation at each $N$.

    The tool we use to calculate $\pi$ is Monte Carlo integration. This method is now elaborated as the following tasks depend on it. Suppose we want to integrate a function $f(x)$ on the interval $\Omega$ where x can have any number of dimensions. We can multiply the integral of $f(x)$ by 1 in the following way:

    \begin{equation}
        \label{eq:int_base}
        \int_{\Omega} f(x) dx = \int_\Omega \frac{f(x)}{p(x)} p(x) dx
    \end{equation}

    where $p(x)$ is a probability density, meaning

    \begin{equation*}
        \int_{\Omega} p(x) dx = 1
    \end{equation*}

    By the law of large numbers we can write \eqref{eq:int_base} as the expectation value of $\frac{f(x)}{p(x)}$:

    \begin{equation}
        \label{eq:expect_value}
        \langle \frac{f(x)}{p(x)} \rangle_{p} = \frac{1}{N} \sum_{i=1}^N \frac{f(x_i)}{p(x_i)} \qquad x_i \sim p(x)
    \end{equation}

    for large $N$ where $x_i$ are randomly drawn from the distribution $p(x)$.

    If $p(x)$ is a uniform distribution it is a constant $\frac{1}{\omega}$ where $\omega$ is the interval length and can be pulled to the left side resulting in the equation

    \begin{equation}
        \label{eq:int_concrete}
        \int_{\Omega} f(x) dx = \frac{\omega}{N} \sum_{i=1}^N f(x_i)
    \end{equation}

    We compare 2 different ways to use this integration to estimate $\pi$.

    \subsubsection{"Integration" method}
    Calculating $\pi/4 = \int_0^1 \sqrt{1-x^2} dx$ using \eqref{eq:int_concrete}
    \subsubsection{Area method}
    Another method is to integrate $\int_0^1\int_0^1 f(x,y) dx dy$ where

    \begin{equation*}
        f(x,y) = \begin{cases}
                     1 & \text{if } x^2 + y^2 \le 1, \\
                     0 & \text{otherwise.}
        \end{cases}
    \end{equation*}

    Again inserting this into \eqref{eq:int_concrete} results into

    \begin{equation*}
        \int_0^1\int_0^1 f(x,y) dx dy = 1/N \sum_{i=1}^N f(x_i, y_i)
    \end{equation*}

    By the definition of $f(x)$ the sum corresponds to the number of samples $x_i$ that land inside of the unit circle, which makes the result of this calculation $\frac{\text{\# samples inside the unit circle}}{\text{\# total number of samples}(N)}
    $, which is a more intuitive way to think about this method.

    \subsubsection{Error}

    As MC integration is a stochastic method we introduce statistical errors with a finite number of samples $N$. We can quantize this error by using the standard deviation of the mean $\sigma_{\bar{f}}$ where $\bar{f}$ is the expectation value resulting from \eqref{eq:expect_value}. For uncorrelated measurements the standard deviation can be calculated in the following way:

    \begin{equation}
        \label{eq:variance_of_mean}
        \sigma_{\bar{f}} = \frac{\sigma_f}{\sqrt{N}}
    \end{equation}

    What this implies, is that an observable with a smaller variance has a smaller statistical error for the estimation. This is the motivation behind using a probability distribution $p(x)$ that minimizes the variance of $\frac{f(x)}{p(x)}$ in equation \eqref{eq:expect_value}. This is called importance sampling and will be used in later tasks.

    \subsection{Results}

    Using a uniform distribution from 0 to 1 with a Mersenne Twister number generation the methods described above were implemented and the resulting estimation of $\pi$ is given at a respective sample size $N$. The results of this are shown in figure \ref{fig:task2-convergence}.

    \begin{figure}[H]
        \centering
        \includegraphics[width=0.8\textwidth]{task2/pi_convergence}
        \caption{Convergence of the area and integration methods to $\pi$. The x-axis shows the number of samples $N$ and the y-axis shows the resulting $\pi$ estimation. The horizontal line corresponds to the true value of $\pi$}
        \label{fig:task2-convergence}
    \end{figure}

    It is clearly visually observable that the integration method converges faster than the area method. The reason for this is that the observable in the integration method has a smaller variance, as can be seen in figure \ref{fig:task2-distribution}.

    With a fixed value of $N=10^6$ the estimation is repeated 1000 times and the results are plotted in a histogram. By the smaller spread (variance) it is clearly visible that the integration method results in a smaller variance. Both methods show normal distributions, centered around the true value of $\pi$, which means they converge to $\pi$ as N goes to infinity.

    \begin{figure}[H]
        \centering
        \includegraphics[width=0.8\textwidth]{task2/pi_distribution}
        \caption{Distribution of the area and integration methods to $\pi$. The x-axis shows bins collecting the results of the estimations. The y-axis shows the number of occurrences inside the respective bin.}
        \label{fig:task2-distribution}
    \end{figure}

    The resulting mean values are:

    \begin{align*}
        \bar{\pi}_{area} = 3.1416 \pm 0.0016 \\
        \bar{\pi}_{int} = 3.14154 \pm 0.00091
    \end{align*}

    where the error is the standard deviation of the means. In practice you would not have to repeat the estimations for this, but use equation $\eqref{eq:variance_of_mean}$ instead as shown earlier.

    With these results it can be concluded that the integration method is more effective, which means the approximation is on average closer to the real result given the same $N$.

    \section{Task 3}\label{sec:task-3}
    \subsection{Description and methods}

    The goal of this exercise is to approximate following integrals using MC integration:

    \begin{equation}\label{eq:ints_to_calc}
        I_1 = \int_0^5 \tau \, Q(\tau) \, d\tau, \qquad
        I_2 = \int_0^5 \tau^2 \, Q(\tau) \, d\tau, \qquad
    \end{equation}

    with

    \begin{equation}
        \label{eq:Q}
        Q(\tau) = \exp(-\alpha\tau),
    \end{equation}

    where $\alpha$ is set to 1 for this task and $Q$ is used as an unnormalized probability distribution.

    In the previous section \ref{sec:task_2} the concept of importance sampling was hinted at. For this integration this technique is used by choosing the probability distribution function:

    \begin{equation*}
        p(\tau) = \frac{Q(\tau)}{Z} \qquad Z = \int_0^5 Q(\tau) d\tau
    \end{equation*}

    Now $I_1$ can be solved using

    \begin{equation}\label{eq:task3_integrals}
        I_1 = Z \times \frac{\int_0^5 \tau Q(\tau) d\tau}{Z} = Z \times \langle \tau \rangle_{Q(\tau)}
    \end{equation}

    where $\langle \tau \rangle_{Q(\tau)}$ is the expectation value of $\tau$ where its values are distributed according to $Q(\tau)$. The resulting expectation value can be calculated according to equation \eqref{eq:expect_value}.

    It is not always trivial to find a procedure to generate random samples $\tau_k$ according to some distribution. When the normalization factor $Z$ is analytically known it is possible to obtain a set of values $x_k$, distributed according to a p(x) by using CDF inversion, which is demonstrated on the following example: We are trying to generate random $\tau$ distributed according to $\exp(-\tau)$. We can relate a random number from the uniform distribution from 0 to 1 $\xi$ to a random sample $\tau$ from the desired function $f(x)$ using the following equation:

    \begin{equation}\label{eq:cdf-inversion}
        \xi = \frac{\int_{\tau_{min}}^{\tau} f(x) dx}{\int_{\tau_{min}}^{\tau_{max}} f(x) dx}
    \end{equation}

    In our case $\tau_{min}=0$ and $\tau_{max}=5$. When solving equation \eqref{eq:cdf-inversion} for $\tau$ the result is:

    \begin{equation}\label{eq:tau_generation}
        \tau(\xi) = -\ln(1 - \xi Z)
    \end{equation}

    which gives us an equation to draw random $\tau$ values from the distribution $Q(\tau)$.

    \subsection{Results}

    The results for generating $N=10^5$ samples obtained by using CDF inversion can be observed in figure \ref{fig:task3-cdf_histogram}.

    \begin{figure}[H]
        \centering
        \includegraphics[width=0.8\textwidth]{task3/cdf_histogram}
        \caption{Normalized Histogram of $10^5$ randomly generated values distributed according to $p(\tau)$ using CDF inversion, and plot of exact function p($\tau$) for comparison.}
        \label{fig:task3-cdf_histogram}

    \end{figure}

    The histogram is normalized in the following way:

    \begin{equation*}
        \text{height}(bin_i)=\frac{\text{sum}(bin_i)}{N\times w}
    \end{equation*}

    where $w$ is the width of the bin and $N$ the number of samples.

    The normalization factor $Z$ is calculated analytically:

    \begin{equation*}
        Z=1-\exp(-5)
    \end{equation*}

    The final integrals are calculated according to \eqref{eq:task3_integrals} using Monte Carlo integration with $N=10^6$ samples drawn via CDF inversion. The error on each estimate is the standard deviation of the mean, $\sigma_{\bar{f}} = \sigma_f/\sqrt{N}$, computed from the sample variance of the integrand. This yields

    \begin{align*}
        I_1 &= 0.9599 \pm 0.0009, \\
        I_2 &= 1.7521 \pm 0.0032.
    \end{align*}

    Both results agree with the analytic values $I_1 = 1-6e^{-5} \approx 0.9596$ and $I_2 = 2-37e^{-5} \approx 1.7507$ within one to two standard deviations, as expected for an unbiased estimator. One interesting fact to note is the choice of $p$ as being proportional to $Q$. This way the expectation value is only dependent on $\tau$ (because $Q$ is now used as part of the probability density), where we know the variance can at worst be of the same order as $\tau$ in the chosen interval. Had we used a uniform distribution the variance and therefore the error could have been far worse as the expectation value would be of the whole function to integrate.

    \section{Task 4}\label{sec:task4}

    \subsection{Description and methods}

    The goal of this task is to replicate the sampling of $Q(\tau, \alpha)$ using a Markov Chain Monte Carlo method. It is not always possible to solve the integrals needed for CDF inversion \eqref{eq:cdf-inversion} analytically which creates the necessity for another method to create samples distributed according to some function $Q$. In these cases we need a Markov Chain procedure (MCMC). In MCMC we generate a chain where each new sample is generated stochastically and then accepted or rejected based on a given procedure. The condition that always has to hold for an update rule of the chain is detailed balance\cite{advanced_comp_physics_script}:
    
    \begin{equation}\label{eq:detailled_balance}
        f(x)p(x \rightarrow y) = f(y)p(y \rightarrow x) \qquad \text{for all states x,y}
    \end{equation}

    Where $f$ is the target distribution and $p(x \rightarrow y)$ is the probability to transition from state x to y. In most algorithms $p$ is split into a generation probability $p_{gen}$ which gives the probability of generating a proposed new state as a next step in the chain and an acceptance probability $p_{acc}$ which is the probability of accepting a generated move. In this instance the Metropolis algorithm was used, in which the acceptance probability of going from a configuration x to y is given as

    \begin{equation}
        \label{eq:metropolis}
        p_{acc}(x\to y)= \min\left\{ 1, \frac{f(y)}{f(x)} \frac{p_{gen}(y\to x)}{p_{gen}(x\to y)} \right\}
    \end{equation}

    where $f$ is the target distribution. Using this procedure we can directly sample from the normalised distribution $\hat{f}$ without the need for any closed form invertible integral solution, and not even the need to know the normalization constant $Z$ as it is cancelled out in the acceptance probability. \\

    Using the proposed generation probability of just $p_{gen}(x)=U(0,5)$ works and generates the correct distribution. It also has the advantage that subsequent samples are less correlated than a local move but for most problems a uniform distribution looks very different than the desired distribution which leads to a small acceptance probability because the random sample will often fall into regions with a low probability density and not pick up the peaks as quickly. This can be improved by generating a proposed displacement inside a box around the current iteration point, instead of uniformly generating a new proposal point in the whole interval. I used the following procedure: Generating a proposed displacement of $\delta \cdot (\xi-\frac{1}{2})$ where $\delta$ is the width of the interval that the current $\tau$ could possibly be displaced to and $\xi$ is a random number in the interval $[0,1]$. If $\tau_{proposed}$ lies outside of the integration interval the move is automatically rejected. This procedure is symmetric, meaning the generation probabilities cancel out. \\

    $\delta$ is a degree of freedom in this procedure and it affects how big the proposed steps are in the Markov chain, so this procedure does not automatically create an acceptance probability that works better than a uniform distribution. Also the individual samples are now highly correlated, as they directly depend on the previous sample. This means we cannot just use equation \eqref{eq:variance_of_mean} anymore to calculate the error as this will greatly underestimate the error. One way to solve this is to perform a grid search for the optimal $\delta$ using blocking analysis. We separate our $N$ samples into $M$ blocks of $\frac{N}{M}=B$ samples each. If $B$ is larger than the integrated autocorrelation time $\tau_{int}$ of the observable which is sampled, this means that each block is uncorrelated to any other and the trivial formula for the standard deviation of the mean can be recovered in the following way:

    \begin{equation*}
        \sigma_{\bar{A}}^2 = \frac{\sigma_{A^{(M_i)}}^2}{M}
    \end{equation*}

    where $A^{(M_i)}$ is the mean value of observable $A(x)$ in block $M_i$. \\

    If $\tau_{int}$ is known we can also define an effective number of independent samples $M_{eff}$ and calculate the variance of the mean using $\sigma_{\overline{A}}^2 = \frac{\sigma_A^2}{M_{eff}}$ where

    \begin{equation}
        \label{eq:m_eff}
        M_{eff} = \frac{N}{2\tau_{int}}
    \end{equation}

    From this we can see that minimizing $\tau_{int}$ is equivalent to maximizing the amount of independent samples for a given $N$ and therefore leads to the lowest possible statistical error in the sample average. Even though this kind of optimization is not necessary for the simple task given, it is nevertheless done for educational purposes in the following way: \\

    Trial values for $\delta$ are chosen from a logarithmic distribution from 0.1 to 100. For each $\delta$ the autocorrelation time is calculated by doing a block analysis. The mean value and variance of the block average for a gradually increasing block size $B$ are calculated with a sample size of $N=1,000,000$. Block sizes where $M<50$ are discarded due to statistical noise. At some block size the variance converges, indicating that at this size the blocks are uncorrelated. This value can be inserted into equation \eqref{eq:m_eff} to get $\tau_{int}$. The $\delta$ with the lowest $\tau_{int}$ can be computed this way. This analysis is of course quite computationally expensive for real problems and therefore only really makes sense as a starting point if multiple MC simulations for similar problems are computed where the result can be reused. However, the block analysis part for a given $\delta$ is necessary to compute an accurate statistical average and will be used to calculate the statistical errors in the subsequent tasks.

This would again imply that each draw is uncorrelated and we do not need to do any blocking analysis. For the cases where sampling from the target distribution is not possible it is generally not desirable to have an acceptance probability close to 1, as this would lead to a very high autocorrelation time.

    \section{Task 5}
    \label{sec:task-5}

    The goal of this task is to introduce the notation of Diagrammatic Monte Carlo. We start by considering only $0^{th}$ order diagrams of the following form:

    \begin{equation}
        \label{eq:0th_order_D}
        \begin{tikzpicture}[baseline=-0.5ex]
            % Draw the diagram line
            \draw[thick] (0,0) -- (3.5,0);

            % Node labels below the line
            \node[below] at (0,0) {$0$};
            \node[below] at (1.75,0) {$\alpha$};
            \node[below] at (3.5,0) {$\tau$};
        \end{tikzpicture}
        \quad = D_0(\tau, \alpha) = \exp(-\alpha \tau)
    \end{equation}

    where $D_0$ is the weight of the diagram. It takes a similar form as \eqref{eq:Q}, but in this task $\alpha$ will not be fixed, but also be taken into account in the Metropolis procedure. To achieve this, in each iteration either $\tau$ or $\alpha$ is updated with equal probability. The procedure for updating $\tau$ stays the same as in section \ref{sec:task4}, while the proposed $\alpha$ value is drawn uniformly from the set $\{0.5,1\}$.

    The resulting histograms for $N=10^6$ samples, split by the $\alpha$ value at each sample, are given in figure \ref{fig:task5-alpha}.

    The correctness of the code can be verified by again calculating the integral results from the samples with the corresponding $\alpha$ values, using the same block analysis as in section \ref{sec:task4} to obtain the error bars. Of course this will also give two new integration results corresponding to the integral associated with $Q(\alpha=0.5, \tau)$, which we call $I_3$ and $I_4$ in analogy to $I_1$ and $I_2$.

    We can reuse the formula we used before \eqref{eq:task3_integrals}, except that we need to calculate the normalization factor for $I_3$ and $I_4$ where $\alpha=0.5$ which is calculated analytically to be $Z_{0.5} = 2 (1 - \exp(\frac{-5}{2}))$. The results for the full integrals are

    \begin{align*}
        I_1 &= 0.9540 \pm 0.0044 \\
        I_2 &= 1.724 \pm 0.014 \\
        I_3 &= 2.8442 \pm 0.0099 \\
        I_4 &= 7.254 \pm 0.041
    \end{align*}

    $I_3$ and $I_4$ agree with the analytic values $I_3 \approx 2.8508$ and $I_4 \approx 7.2990$ within one standard deviation. $I_1$ and $I_2$ are somewhat further off, at $\approx 1.2$ and $\approx 1.9$ standard deviations from $I_1 \approx 0.9596$ and $I_2 \approx 1.7507$ respectively. This is a larger deviation than seen in section \ref{sec:task4}, but still consistent with a statistical fluctuation of a single run rather than a systematic error. Something to note here is that the standard deviation itself is bigger. The reason for this is that we have the same number of samples, but with the added degree of freedom $\alpha$ fewer samples actually contribute to their integrals leaving fewer total samples per integral.

    \section{Task 6}

    \subsection{Description and methods}
    In this task the goal is to introduce higher order diagrams. The equation of interest is now the following

    \begin{equation}\label{eq:Q_order_2}
        Q(\tau, \alpha, V)= e^{-\alpha\tau}+\sum_{\beta}\int_0^{\tau} d\tau_2 \int_0^{\tau_2} d\tau_1 e^{-\alpha\tau_1} V e^{-\beta(\tau_2-\tau_1)}V e^{-\alpha(\tau-\tau_2)}
    \end{equation}

    This is just the sum of 0th order and 2nd order diagrams with all internal variables integrated out. $D_0(\tau, \alpha)$ just stays the same as in the previous tasks and the 2nd order diagram takes the following form:

    \begin{equation*}
        \label{eq:2nd_order_D}
        \begin{tikzpicture}[baseline=-0.5ex]
            % Draw the diagram line
            \draw[thick] (0,0) -- (5.25,0);

            % Vertex markers
            \filldraw (1.75,0) circle (1.5pt);
            \filldraw (3.5,0) circle (1.5pt);

            % Node labels below the line
            \node[below] at (0,0) {$0$};
            \node[below] at (0.875,0) {$\alpha$};
            \node[below] at (1.75,0) {$\tau_1$};
            \node[below] at (2.625,0) {$\beta$};
            \node[below] at (3.5,0) {$\tau_2$};
            \node[below] at (4.375,0) {$\alpha$};
            \node[below] at (5.25,0) {$\tau$};
        \end{tikzpicture}
        \quad = D_2(\tau, \alpha, V; \tau_1, \tau_2, \beta) = e^{-\alpha \tau_1} \, V \, e^{-\beta(\tau_2-\tau_1)} \, V \, e^{-\alpha(\tau-\tau_2)}
    \end{equation*}

    The 3 arguments of $D_2$ to the left of the semicolon are external variables that in our simulation are $\tau \in [0,5], \alpha=1, V=0.5$. The 3 arguments to the right of the semicolon are internal variables that are integrated out in the evaluation of $Q$. $\beta$ is a discrete variable that can take values from the set $\{0.25, 0.75\}$, $\tau_1$ and $\tau_2$ are points in time with the following conditions: $0 < \tau_1 < \tau_2 < \tau$. The value of $D_i$ corresponds to its weight.

    Two new updates have to be implemented. An update to go from a $D_0$ to $D_2$ called "add-$\beta$" and the reverse from $D_2$ to $D_0$ called "remove-$\beta$". The generation probabilities of these moves are chosen to be equally likely at $0.1$ each which makes them cancel out in the Metropolis-Hastings step. There are multiple ways you could implement this step to satisfy detailed balance. The Metropolis-Hastings step for "add-$\beta$" has to satisfy the following equation:

    \begin{equation}\label{eq:acc_add_beta}
        p_{acc}(D_0 \rightarrow D_2) = \min\left\{ 1, \frac{p_{rem}}{p_{add}} \frac{D_2(\tau, \alpha, V; \tau_1, \tau_2, \beta) \, d\tau_1 d\tau_2}{D_0(\tau, \alpha) \, p_1(\tau_1) p_2(\tau_2) p_3(\beta) \, d\tau_1 d\tau_2} \right\}
    \end{equation}

    where $p_{add}$ and $p_{rem}$ are the context factors, which are the probabilities with which the "add-$\beta$" and "remove-$\beta$" updates are addressed. Since they are equal here, their ratio is $1$, and the differentials $d\tau_1 d\tau_2$ cancel as well.

    When adding a new $D_2$ the internal variables are generated randomly with $\tau_1$, $\tau_2$ from $U(0,5)$ giving this move a probability density of $p(\tau_1) = p(\tau_2)=\frac{1}{5}$ and $\beta$ is chosen with a probability of $0.5$ to be either $\frac{1}{4}$ or $\frac{3}{4}$. If the current diagram in the chain is already 2nd order the move is rejected. If the internal parameters don't satisfy their constraints, the move is also rejected.

    The "remove-$\beta$" step is the inverse of "add-$\beta$" and is chosen in the following way to adhere to detailed balance. Its acceptance probability is the inverse of \eqref{eq:acc_add_beta}:

    \begin{equation}\label{eq:acc_remove_beta}
        p_{acc}(D_2 \rightarrow D_0) = \min\left\{ 1, \frac{p_{add}}{p_{rem}} \frac{D_0(\tau, \alpha) \, p_1(\tau_1) p_2(\tau_2) p_3(\beta) \, d\tau_1 d\tau_2}{D_2(\tau, \alpha, V; \tau_1, \tau_2, \beta) \, d\tau_1 d\tau_2} \right\}
    \end{equation}

    where $\tau_1$, $\tau_2$ and $\beta$ are the internal variables of the current 2nd order diagram, and $p_1$, $p_2$, $p_3$ are the same generation densities that "add-$\beta$" would have used to propose them. If the diagram is again already of order 0, the move is rejected.

    As $\alpha$ is set to 1 for this task, the "change-$\alpha$" move is removed for this simulation. The moves still in place are "change-$\tau$" with a probability of 0.8, and "add/remove-$\beta$" with a probability of 0.1 each.

    In the previous tasks the normalization needed to calculate the integrals was calculated analytically. We are interested in the normalization constant

    \begin{equation}\label{eq:Z}
        Z=\int_0^5 Q(\tau) d\tau = \underbrace{\int_0^5 d\tau\, e^{-\alpha\tau}}_{Z_0}\;+\;
\underbrace{\sum_{\beta \in \{\beta_1,\beta_2\}} \int_0^5 d\tau \int_0^{\tau} d\tau_2 \int_0^{\tau_2} d\tau_1\,D_2}_{Z_2}
    \end{equation}

    This can still be calculated analytically, but for more complicated diagrams that might not be feasible anymore. There is, however, a way to solve this without much extra effort.

    The expectation value for the number of samples that are 0th order diagrams is just:

    \begin{equation*}
        \langle 1[order=0] \rangle_Q = \frac{\int_0^5 1[order=0] Q(\tau) d\tau}{\int_0^5 Q(\tau) d\tau} = \frac{Z_0}{Z}
    \end{equation*}

    The numerator collapses to exactly $Z_0$ as defined in \eqref{eq:Z} as only the contributions from diagrams with order 0 survive the 1[order=0] which results exactly in $Z_0$. A counter is implemented that counts the number of 0th order diagrams. This number in turn can be used to calculate an approximation of $Z$:

    \begin{equation}\label{eq:Z_final}
        Z \approx \frac{Z_0}{N_0} \times N
    \end{equation}

    where $N_0$ is the number of samples that are order 0 diagrams. For this we still have to calculate $Z_0$ analytically, but with this knowledge alone we could add any order diagrams and still calculate $Z$ using the same procedure. One thing to note is that $N_0$ can't be too small, otherwise statistical errors will lead to a bad estimation, which is not a problem for this simulation though. This statistical error in $Z$ does however change how the overall error of the integration can be calculated.

    Currently the error is derived from the variance of the block means in the blocking analysis, where the variance has converged with increasing block size meaning that the blocks are uncorrelated. This gives us the statistical error $\delta(\langle f(\tau) \rangle)_Q$, which in our integrals of interest is still multiplied by the normalization factor $Z$ \eqref{eq:task3_integrals}. But $Z$ itself has a statistical error now which is correlated with the error for the expectation value. This is solved here by including the normalization factor $Z$ into the calculation of the block means inside the blocking analysis itself. So I calculate the estimation for $Z$ in each block and calculate the variance of the full integral evaluated at each block in the same way I would do with the resulting sample mean of the observable of interest.

    \subsection{Results}

    The simulation was run for $N=10^7$ samples with $\delta=10$ and $p_{add} = p_{rem} = 0.1$. The resulting histogram binned by $\tau$ is shown in figure \ref{fig:task6-distribution}

    \begin{figure}[H]
        \centering
        \includegraphics[width=0.8\textwidth]{task6/histogram}
        \caption{Normalized Histogram of points sampled and binned to $\tau$ values. The x-axis shows bins for the respective $\tau$ values. The y-axis shows the normalized occurrence count. The target probability distribution is also drawn for comparison.}
        \label{fig:task6-distribution}
    \end{figure}

    The results of the integrals $I_1$ and $I_2$, as they are defined in \eqref{eq:ints_to_calc} with the new definition of $Q$ \eqref{eq:Q_order_2} which includes 2nd order diagrams are:

    \begin{align*}
        I_1 &= 3.225 \pm 0.038 \\
        I_2 &= 9.37 \pm 0.16 \\
    \end{align*}

    The exact result for $I_{1,exact}$ is $3.2043$ which makes the difference quite close to the calculated error at 0.020. Also for $I_2$ the estimation is within 1 standard deviation from the correct result at $I_{2,exact} = 9.28169$ (difference of 0.093). The reference results were calculated numerically up to a precision that is higher than our MC simulation.

    There are many ways to improve this simulation. The internal parameters for $D_2$ could always be generated in a valid way, which would make the acceptance probability calculation just slightly more complicated but lead to more "add-$\beta$" steps being accepted. Also there could be a probability added to change the internal variables of $D_2$ which would likely sample a greater range of 2nd order diagrams more quickly leading to a smaller autocorrelation time and therefore a more accurate result. The probabilities of executing "add"- or "remove-$\beta$" can also all be tuned in order to achieve the smallest possible autocorrelation time if this is something one tries to optimize for. For example, a higher value for "add/remove-$\beta$" would very likely increase the accuracy, as there are more configurations in 2nd order diagrams to sample.

    Note that the only integral that had to be calculated analytically was $Z_0$. A set of samples was created according to a desired distribution $Q$ without ever having to calculate the full normalization.

    The main sampling loop:

    \begin{lstlisting}[style=cppstyle, caption={The function that actually samples diagrams. obs\_values stores the sampling points that are later used for blocking. There is a d\_curr which always stores the current full diagram to save memory. Based on the probabilities provided one of the changes will be executed and it will calculate the acceptance probability internally based on the kind of change and just return the acceptance probability p\_acc, based on which the move is accepted or rejected }, label={lst:sample_diagrams}]
        std::vector<sampling_point> sample_diagrams(std::mt19937& rng, int N = 1'000'000)
{
    std::uniform_real_distribution<> random_uniform(0, 1);

    D d_init = {.order = 0, .alpha = 1, .tau = random_uniform(rng) * 5};

    std::vector<sampling_point> obs_values = {{d_init.order, d_init.tau}};
    D d_curr = d_init;
    obs_values.reserve(N);
    for (int i = 1; i < N; i++)
    {
        D d_new = d_curr;

        double rand = random_uniform(rng);
        double p_acc;
        if (rand < P_add)
            add_beta(d_new, d_curr, rng, p_acc);
        else if (rand > (1 - P_rem))
            remove_beta(d_new, d_curr, p_acc);
        else
            change_tau(d_new, d_curr, rng, p_acc);
        // Here additional changes like change_alpha, or change_tau_1, etc. could be added in the same way the others are

        if (random_uniform(rng) < p_acc)
        {
            obs_values.push_back({d_new.order, d_new.tau});
            d_curr = d_new;
        }
        else
        {
            obs_values.push_back({d_curr.order, d_curr.tau});
        }
    }
    return obs_values;
}
    \end{lstlisting}

    The individual changes to the diagrams are done in the following way:

    \begin{lstlisting}[style=cppstyle, caption={Examples of proposed changes to the diagram. They propose some new move and calculate the Metropolis-Hastings step and write to p\_acc with the result}, label={lst:changes}]
        void change_tau(D& d_new, D& d_curr, std::mt19937& rng, double& p_acc)
{
    std::uniform_real_distribution<double> random_uniform(0, 1);

    d_new.tau = d_curr.tau + DELTA * (random_uniform(rng) - 0.5);

    p_acc = std::min(1., target_pdf(d_new) / target_pdf(d_curr));
}

void add_beta(D& d_new, D& d_curr, std::mt19937& rng, double& p_acc)
{
    std::uniform_real_distribution<> random_uniform(0, 1);
    std::bernoulli_distribution random_bernoulli(0.5);

    if (d_curr.order == 2)
    {
        p_acc = 0;
        return;
    }

    if (d_curr.order == 0)
    {
        d_new.order = 2;
        d_new.tau_1 = random_uniform(rng) * 5;
        d_new.tau_2 = (5 - d_new.tau_1) * random_uniform(rng) + d_new.tau_1;
        d_new.beta = random_bernoulli(rng) ? 1. / 4 : 3. / 4;
        d_new.V = 0.5;
    }
    p_acc = std::min(1., target_pdf(d_new) / (target_pdf(d_curr) * 1. / (5 - d_new.tau_1) * 1. / 5 * 1. / 2));
}

void remove_beta(D& d_new, D& d_curr, double& p_acc)
{
    d_new.order = 0;
    p_acc = std::min(1., target_pdf(d_new) * 1. / (5 - d_curr.tau_1) * 1. / 5 * 1. / 2 / target_pdf(d_curr));
}

    \end{lstlisting}

    \begin{lstlisting}[style=cppstyle, caption={Function that checks if the proposed diagram is actually valid. If not the acceptance probability is automatically set to 0}, label={lst:valid}]
        bool is_valid(D d)
{
    if (d.order == 0)
        return d.tau >= 0 && d.tau <= 5;
    if (d.order == 2)
        return d.tau_1 >= 0 && d.tau_2 >= d.tau_1 && d.tau >= d.tau_2 && d.tau <= 5;
    throw std::runtime_error("Only order 0 and 2 diagrams are implemented so far!");
}
    \end{lstlisting}

    \begin{lstlisting}[style=cppstyle, caption={The diagram weights that are being sampled.}, label={lst:target_pdf}]
double target_pdf(D d)
{
    if (!is_valid(d)) return 0;
    if (d.order == 0)
        return std::exp(-d.tau * d.alpha);
    if (d.order == 2)
    {
        return std::exp(-d.alpha * d.tau_1) * d.V * std::exp(
            -d.beta * (d.tau_2 - d.tau_1)) * d.V * std::exp(-d.alpha * (d.tau - d.tau_2));
    }
    throw std::runtime_error("Order should only be 0 or 2!");
}

    \begin{lstlisting}[style=cppstyle, caption={Block analysis as described in \ref{sec:task4}. This calculates the mean and also the variance by gradually increasing block sizes and calculating the variance of the block means. A cumulative sum is used so that block means turn from a sum over B values into just one subtraction}, label={lst:block-analysis}]
template <typename Func>
block_analysis_result block_analysis(Func observable, std::vector<sampling_point>& sample_points)
{
    int N = sample_points.size();

    std::vector<double> observables;
    observables.reserve(N);

    std::vector<int> order_0_points = {0};
    order_0_points.reserve(N + 1);

    for (const auto& point : sample_points)
    {
        observables.push_back(observable(point));
        order_0_points.push_back(order_0_points[order_0_points.size() - 1] + (point.order == 0 ? 1 : 0));
    }

    std::vector cumulative_sum{0.};
    cumulative_sum.resize(sample_points.size() + 1);

    std::partial_sum(observables.begin(), observables.end(), cumulative_sum.begin() + 1);

    double mean = cumulative_sum.back() / N;

    std::vector<block_variance_result> block_variance_results;
    int B = 1;

    bool plateau_found = false;
    std::vector<block_variance_result> plateau_points;

    while (N / B > 50)
    {
        int M = N / B;

        std::vector<double> block_means;
        block_means.reserve(M);

        for (int b = 0; b < M; b++)
        {
            double block_mean = (cumulative_sum[(b + 1) * B] - cumulative_sum[b * B]) / (order_0_points[(b + 1) * B] -
                order_0_points[b * B]);
            block_means.push_back(block_mean);
        }

        double block_mean_avg = std::accumulate(block_means.begin(), block_means.end(), 0.) / M;
        double block_mean_variance = std::accumulate(block_means.begin(), block_means.end(), 0.,
                                                     [block_mean_avg](double sum, double value)
                                                     {
                                                         double diff = block_mean_avg - value;
                                                         return sum + diff * diff;
                                                     }) / M;
        double mean_variance = block_mean_variance / M;
        block_variance_results.push_back({.B = B, .mean_variance = mean_variance});

        if (block_variance_results.size() > 1 && std::abs(
                block_variance_results.back().mean_variance - (block_variance_results.rbegin() + 1)->mean_variance) <
            delta_variance(block_variance_results.back().mean_variance, M))
            plateau_found = true;

        if (plateau_found)
            plateau_points.push_back({.B = B, .mean_variance = mean_variance});

        B *= 2;
    }

    double plateau_variance = std::accumulate(plateau_points.begin(), plateau_points.end(), 0., [N](double sum, const block_variance_result&block_variance)
                                              {
                                                  return sum + 1 / std::pow(
                                                      delta_variance(
                                                          block_variance.mean_variance, N / block_variance.B),
                                                      2) * block_variance.mean_variance;
                                              }) / std::accumulate(plateau_points.begin(), plateau_points.end(), 0.,
                                                                   [N](double sum,
                                                                       const block_variance_result& block_variance)
                                                                   {
                                                                       return sum + 1 / std::pow(
                                                                           delta_variance(
                                                                               block_variance.mean_variance,
                                                                               N / block_variance.B), 2);
                                                                   });

    double autocorrelation_time = 1. / 2 * plateau_variance / block_variance_results.front().mean_variance;

    if (plateau_points.empty())
        return {.success = false, .autocorrelation_time = -1, .mean = mean, .mean_variance = -1};
    return {
        .success = true, .autocorrelation_time = autocorrelation_time, .mean = mean, .mean_variance = plateau_variance
    };
}
